# WB27: the circuit holds the full 27-bit weight pointer

Tags: [V] verified (log cited), [M] measured, [D] designed, not built/run.
Code: `ramown/wb27/wb27.py` (source patch of Qwenputer-npu `2717232` `experimental/riscv/chipformer/rv/core.py`, applied like the other bring-up patches: string replace + exec), `ramown/wb27/test_wb27.py` (IR test), `fullrun/circuit_run.py` (`WB27=1`, block marked `WB27`), `ramown/wb27/modal_wb27.py` (Modal runner). Logs: `ramown/wb27/logs/`.

## Design

Before: the WB uop computed `wb.d = x[rs1][15:0] + ~w (4-nibble adder) [:15]`, the WB token carried it, the 1-slot latch head `wbase` (L1) took it from the token payload. Bits 15..26 existed only in the host (reference / injection schedule).

After (two changes in the circuit, one in the snapshot):
1. The WB adder `wb.d` is widened to 7 nibbles: `wb27 = x[rs1][27:0] + (~w, the 16-bit complement extended with ones in bits 16..27) mod 2^27 = (x[rs1] - (anchor + n) - 1) mod 2^27`. The borrow out of the low 15 bits and the wrap are carried by the same carry-lookahead adder; x[rs1] bits 27..31 drop out mod 2^27. Bits 0..14 are the same function as before, so the WB token (family WB, 15-bit payload) is unchanged: trace, vocabulary and the existing 6/20-chunk chain results stay valid.
2. New 1-slot latch head `wbase_hi` (cols 2..13 = wb27 bits 15..26), written by the circuit's own adder output at the position where the WB uop executes. Write gate = the WB case's own literals (`nr + [wbop]` (+`nb`)), i.e. exactly where the circuit emits the WB token; an R refresh (n = 63) or a fault does not write. It lands in the last layer's attention (sublayer level 21; `wbase` is level 1).
3. `snapshot()` initialises `wbase_hi` from `m.wb27 >> 15` (only the step-0 state restore of a chain uses it).

The circuit's pointer is `wbase | wbase_hi << 15`. Timing: `wbase_hi` is written one position before `wbase` (exec position vs WB-token position); at the exec position only the high part is already new (tested separately). The WROM / injection path is untouched: WROM addressing still uses `WP = wbase + w mod 2^15`, the host's VDOT injection still writes at `WP mod 2^15`.

Optional (off in the chain runs): `wp27` adder, the VDOT weight address `WP27 = wbase27 + w mod 2^27` (= the reference's `(wb + i) & M27`, i the VDOT's word index, PC = 0x40000 + 4 i). Not consumed by anything.

wp27 costs a layer because `wbase_hi` is read in the last layer; to make it free, compute the high VDOT address from the register at WROW/WB time instead (see composition) or move the hi latch earlier (needs `A` earlier; not done).

Executor speed [M] (fused FreeRun3, A100-80GB on Modal, chunk 0, 300,000 steps, separate containers): 5,185 tok/s with WB27, 5,471 tok/s without (`logs/speed_wb27.stdout`, `logs/speed_base.stdout`): about 5 % slower, same order as container-to-container noise; the WB27 chain ran at 5,22x tok/s vs 5,525 tok/s for the lambda-final A100-40GB baseline chain.

## Validation

(1) [V] Tiny firmware, IR `evaluate(check=True)` teacher-forced (`test_wb27.py`, `logs/test_wb27.log`): 4 programs, 130 WB records with x[rs1] in {0, 3, 0x7FFF, 0x8000, 0x05ABC123, 0x07FFFFFF, 0x0400_0000, 0xFFFFFFFF, 0x80001234, 0x12345678, random 32/27-bit, small (borrow), 2^27 - small}. Reference = `ref.Machine` with `S.WP_BITS = 27` (WB payload masked to 15 bits for the token, WROM read mod 2^15), whose trace equals the 15-bit machine's. Results: 0 token mismatches; circuit `wbase|wbase_hi<<15` (decoded from the head read outputs) equals the 27-bit reference at all 1,367 steady positions (0 mismatches), the high latch equals the new value at all 130 exec positions; 126 of 130 WB values have non-zero upper bits, 59 are borrow wraps (x[rs1] < anchor + n + 1, e.g. 0x7ffffe2 from x = 0), 12 R refreshes interleave. With wp27 (`logs/test_wp27.log`): all 329 reference VDOT addresses (wb27 + i mod 2^27, 262 with non-zero upper bits) appear in order in the circuit's wp27.

## Circuit vs host, exactly

- Circuit-computed: the full 27-bit pointer (low 15 from the WB token the circuit emits itself, high 12 from the circuit's adder into `wbase_hi`), held across chunk boundaries.
- Host, still: the step-0 snapshot of chunk 0 (wb = 0 there, all registers); nothing is written to `wbase_hi` after step 0. The host's injection schedule still contains its own 27-bit VDOT address (the precomputed look-ahead picks the 8 cells from the 596 MB file at `wb + i`), so the host still *uses* its copy; the circuit's copy is not yet consumed by any weight path (WROM uses the low 15 bits). The VDOT weight words themselves remain host-injected.

## Composition with the WROW path (weight_fetch, `wf_npu.patch`) [D]

In the WROW design the row id `r = x[rs1][17:0]` comes from a register (the firmware computes it), so the high address bits are in the register file by construction and WB27 is not needed for addressing; the window inside the row comes from `WP[ROW_SLOT_BITS-1:0]` of the 15-bit WP, unchanged by WB27. With WB27 the circuit also holds `WP27 = wbase27 + w mod 2^27` (option above), so the weight word addressed by a VDOT is `WP27`; with rows laid out on 2^ROW_SLOT_BITS-word boundaries the row id would be `WP27 >> ROW_SLOT_BITS` and could be checked against (or replace) the register-supplied `r`, i.e. a WROW without rs1. Not built; it would need the hi latch earlier than the last layer to avoid the +1 layer.
